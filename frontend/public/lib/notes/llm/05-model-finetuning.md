# 模型微调：SFT、LoRA与RLHF在做什么

提到"微调"很多人第一反应是"要海量数据和 GPUs 集群"。其实恰恰相反：**微调的门槛已经降到了消费级显卡就能玩**，真正的难点是搞清楚——什么时候该微调，什么时候不该。

## 先回答：该微调吗？

微调前先过一遍这个决策链：

| 需求 | 推荐方案 |
|------|---------|
| 补充事实知识（文档、FAQ） | RAG |
| 改变回答风格、格式、语气 | 微调（SFT） |
| 稳定输出特定 JSON 结构 | 先试 Prompt，不行再微调 |
| 提升某个垂直领域的能力 | 微调 + 领域数据 |
| 让模型更符合人类偏好 | RLHF / DPO |

一个粗略的记忆点：**RAG 注入"知识"，微调改变"行为"**。想让模型记住产品手册用 RAG；想让模型永远用特定口吻说话、稳定输出某种格式，微调。

## SFT：指令微调

SFT（Supervised Fine-Tuning，监督微调）是最基础的微调方式：拿一批"指令 → 期望回答"的数据对，继续用交叉熵损失训练模型。

数据格式（以 Alpaca 格式为例）：

```json
{
  "instruction": "把下面的句子翻译成英文",
  "input": "今天天气真好",
  "output": "The weather is really nice today."
}
```

关键点不在训练，而在**数据质量**：

- 1000 条精标数据，往往胜过 10 万条网上爬的脏数据（LIMA 论文的核心结论）
- 数据分布要覆盖真实使用场景，而不是只盯着典型样本
- 谨防"灾难性遗忘"：全量微调可能让模型丢掉通用能力，混合一部分通用数据可缓解

## LoRA：参数高效微调

全量微调一个 7B 模型，权重 + 优化器状态需要上百 GB 显存。LoRA（Low-Rank Adaptation）的思路让它降了一个数量级：

### 直觉理解

研究发现微调时权重的**变化量 ΔW 是低秩的**——可以把它分解成两个小矩阵的乘积：

```
原权重 W (d × d)          冻结不动
变化量 ΔW ≈ A × B          A: d × r,  B: r × d,  r << d (如 r=8)
```

训练时只更新 A 和 B，推理时把 `B·A` 加回原权重。对于 7B 模型，可训练参数从 70 亿降到千万级，**显存需求从 ~80GB 降到 ~16GB，一张 RTX 4090 就能跑**。

### 实操

```python
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=8,                      # 秩，越大表达能力越强、越容易过拟合
    lora_alpha=16,            # 缩放系数，通常取 r 的 2 倍
    target_modules=["q_proj", "v_proj"],  # 通常只挂在注意力层
    lora_dropout=0.05,
)
model = get_peft_model(base_model, lora_config)
```

衍生优势：LoRA 适配器只有几十 MB，**一个底座模型可以挂多个适配器**，按需热切换——"一个模型服务多个业务风格"成为可能。QLoRA 进一步把底座量化到 4-bit，单卡微调 33B 模型成为现实。

## RLHF与DPO：对齐人类偏好

SFT 教会模型"怎么答"，RLHF（Reinforcement Learning from Human Feedback）教会它"哪种回答更好"。

### RLHF 三步走

1. **SFT 起步**：先有会说话的模型
2. **训练奖励模型（RM）**：人类对多个回答排序，训练一个给回答打分的模型
3. **强化学习优化（PPO）**：让 LLM 生成回答、RM 打分，用 PPO 算法迭代优化——追求高分同时用 KL 散度惩罚防止跑偏

### DPO：不要奖励模型的RLHF

DPO（Direct Preference Optimization）的洞察是：**奖励模型可以数学上等价地"折叠"进训练目标里**。直接拿"好回答 / 差回答"配对数据做分类式训练，一步到位：

```json
{
  "prompt": "如何学好编程？",
  "chosen": "建议从项目实战入手……（详细、结构化）",
  "rejected": "多写代码就行了。"
}
```

DPO 训练稳定性好、资源占用接近 SFT，已成为开源社区对齐的主流选择。

## 不想写代码？用现成工具

- **LLaMA-Factory**：Web UI 一站式微调，支持主流开源模型和 LoRA/QLoRA/DPO
- **Unsloth**：单卡微调提速 2 倍、省显存 70%，适合个人玩家
- **PEFT + TRL**（HuggingFace 官方）：需要灵活控制时的代码方案

## 常见的坑

- **拿微调当知识库用**：微调很难精确"记住"事实，还容易编造——知识注入请用 RAG
- **数据没清洗**：哪怕 1% 的坏样本也会明显拉低效果
- **学习率过大**：微调学习率通常比预训练小 1~2 个数量级（1e-5 ~ 2e-4），过大直接"训废"
- **不建评测集**：没有固定的评测基准，就分不清"感觉变好了"和"真的变好了"

## 小结

- **SFT** 教行为，**LoRA** 让微调平民化，**RLHF/DPO** 对齐偏好
- 动手前先问：这个问题 Prompt 或 RAG 能不能解决？大概率能
- 真要微调时，把 80% 的精力花在数据质量上——数据决定上限，训练只是把上限兑现
