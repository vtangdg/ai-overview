# AI应用开发工程师学习路径

这篇是全站笔记的"导航枢纽"：把散落的知识点串成一条可执行的学习路线。路线设计遵循一个原则——**每个阶段都有明确的完成标志**，没有产出的学习都算没学完。

## 总览：五个阶段

```
语言基础 → LLM认知 → 核心模式 → 工程化 → 进阶深耕
 (1个月)    (2周)     (1-2个月)    (1个月)    (持续)
```

阶段时长因人而异，供参考的是比例而非绝对值：**阶段 3 和 4 占总投入的一半以上**——它们是从"学过"到"会做"的关键。

## 阶段一：语言与基础

**学什么**：Python（AI 生态的通用语言）、HTTP/API 调用、SQL、Git。

- Python 不需要精通，能读写脚本、会装包（pip/uv）、懂基础异步即可
- 重点放在**调 API 的能力**：认证、JSON 处理、错误重试
- SQL 别跳过：做 RAG 时元数据管理、日志分析都离不开

**完成标志**：能独立写脚本调通任意一个 REST API，并把结果存入数据库。

## 阶段二：LLM 基础认知

**学什么**：

- [Prompt 工程指南](/notes/02-prompt-engineering)——怎么把话说清楚让模型干活
- [Token与上下文窗口](/notes/03-tokens-and-context)——模型的"记账规则"，直接决定成本
- 动手：注册任意一家大模型 API，跑通第一次对话调用

这个阶段的要点是**建立"边界感"**：知道模型擅长什么、不擅长什么，比学会任何技巧都重要。别急着学框架——连 API 都没调熟就上 LangChain，只会多一层看不懂的抽象。

**完成标志**：针对一个真实任务（如抽取合同关键字段）写出 Prompt，并做 3 个版本的对比实验，说清差异原因。

## 阶段三：核心应用模式（分水岭）

这是整条路线的分水岭：之前是"学知识"，之后是"做工程"。

**学什么**（按顺序）：

1. [RAG从零到一](/notes/03-rag-basics)——企业落地第一刚需
2. [Agent与Function Calling](/notes/04-agent-function-calling)——让模型"动手做事"
3. [Embedding与语义检索](/notes/05-embeddings-and-semantic-search)——文字如何变成可检索的向量

**完成标志**：**独立搭出一个最小 RAG 问答系统**——从文档解析、切分、向量化到检索、生成，跑通全链路。框架不限，甚至可以不用框架手写，收获反而更大。

大部分人会卡在这一步：学了一堆概念却从未拼出完整链路。判断标准很简单——你的系统能对"你的文档"回答"你的问题"吗？

## 阶段四：工程化落地

**学什么**：

- [LangChain快速入门](/notes/01-langchain-quickstart)——用框架减少重复造轮子
- [向量数据库选型实战](/notes/02-vector-databases)——数据存哪里、怎么查
- **[评测（Eval）](/notes/06-eval-basics)**：给自己的 RAG 建一个 20~50 条的评测集
- [可观测与成本治理](/notes/07-observability-and-cost)：记录每次调用的输入输出、耗时、Token 消耗

**完成标志**：你的 RAG 系统有了评测集和指标（召回率、忠实度），改一版切分策略能说出"指标变了多少"——而不是"感觉好了点"。

## 阶段五：进阶与差异化

到了这里，按方向二选一深耕（建议选和本职工作交叉的方向）：

- **效果方向**：[模型微调](/notes/05-model-finetuning)（SFT/LoRA/DPO）、数据工程
- **效率方向**：[本地部署](/notes/03-local-llm)与[推理优化](/notes/08-inference-optimization)（量化、KV Cache）、[成本治理](/notes/07-observability-and-cost)

通用佐料（都值得花时间）：多模态应用、[MCP 生态](/notes/04-mcp-in-action)、AI 安全与合规。

## 三条避坑指南

1. **别从微调入门**——90% 的问题 Prompt 和 RAG 就能解决，微调是最贵的选项
2. **别无脑追新框架**——框架月月出新的背后，核心模式三年没变过：检索、工具调用、编排
3. **别跳过评测**——没有评测集的优化全是玄学，这也是"能跑的 Demo"和"能上线的系统"的分界线
